# 综测助手

本地运行的综测规则分析、算分与赛事资料工具。规则从文件建立；学校、维度、权重、封顶和奖励分不写死在计算引擎中。

## 启动

首次使用需要安装下方依赖，再双击 [Start-Assistant.cmd](Start-Assistant.cmd)，浏览器会在服务就绪后打开。在“更多 → 连接与设置”填写自己的模型服务配置。仓库不包含 API key、本机数据库或已导入材料。默认地址 `http://127.0.0.1:8768`，端口占用时自动选择后续端口，以启动窗口输出为准。

启动器会实际检查依赖，依次尝试项目环境、当前 Python、已登记的 Conda 环境与 PATH 中的 Python；默认 Python 缺依赖时自动切换。运行 `Start-Assistant.cmd --check` 可查看选中的环境。也可用环境变量 `CEA_PYTHON` 指定优先检查的 Python 可执行文件。

需要 Python 3.11+：

```powershell
python -m pip install -r requirements.txt
python scripts/launch.py
```

关闭对应 Python 服务进程即可停止。所有工作资料、模型配置和下载文件在 `.local/`；备份该目录可保存当前工作区。不同学校、学院、学年使用独立规则方案。

## 使用

1. **我的综测**：首页显示当前记录的分数估算、缺失信息、待确认成果和计划净增益，并给出下一步入口。没有记录时点“开始我的测评”即可建立；虚构样例会单独标明，不能当作本人成绩。没有个人数据时不把默认值显示为总分。
2. **成绩成果**：直接上传成绩单、证书或实践证明，提取后用普通表单核对课程、数值和成果类别，可以修正或排除条目，无需编辑 JSON。也可以直接填写。日常修改自动保存，并在资料可计算、规则已启用时自动更新分数；缺失信息会提示补齐。待确认成果不计分，计划项目只作预估。计算后可查看分数依据，导出可读的 `综测估算与材料清单.txt`；完整 JSON 备份与手动保存放在折叠区。
3. **加分机会**：先看已收集公告的条件、材料和明确时间节点，有未来日期的公告优先，已过时间节点的信息保留在折叠区。页面内可筛选已收集公告，也可搜索新公告或粘贴官方通知链接。公告中的比赛日期不等于报名仍开放，是否能参加、是否计分需结合原文条件。检索覆盖、失败和原始来源记录按需展开。
4. **待办**：从公告加入准备事项、来源与日期，或手动添加任务，导出 `.ics` 日历。只有原文能支持的具体日期进入日期字段；“某月”“另行通知”不会补成某一天。
5. **更多**：在“细则解读”直接提问、查看材料要求并回看引用原文；在“资料与细则”管理文件和方案；在“连接与设置”配置模型和搜索。公式、JSON 编辑、结构错误等集中在“规则维护与计算依据”折叠区，日常录入不需要操作这些内容。

首次使用新细则时，首页可直接“上传细则并整理”；同一学校、同一学年的细则和补充通知可以一起选择，也可从“更多 → 资料与细则”选择已有文件。支持 PDF、DOCX、PPTX、XLSX、文本和图片；扫描页需要支持视觉输入的模型，公式和表格保留原始图像供核对。成绩单与获奖证明应在个人记录中添加，不用作细则来源。

**自动整理出的新规则仍是未核验草稿。** 首次使用或修改规则后，需要对照原文核对权重、系数、封顶和例外，再在规则维护中启用；结构或引文错误会阻止启用。自动保存、自动算分不会代替这一步，也不代表模型已经正确理解全部条款。

连接模型时填写服务地址、API key、模型 ID、协议、视觉能力和超时。支持 Chat Completions 兼容服务、Responses、Anthropic，也可接入提供兼容接口的本地模型；设置中提供连接测试和模型列表读取。

服务运行期间可以按设置的间隔自动检索已启用方案。默认免费 Bing 检索并补查官方通知栏目；可换成自有 Tavily 或 SearXNG。官方域名列表按所在学校与主办方配置，不能把未知聚合站当作官方来源。

- 用户指定的武汉大学计算机学院 2025 修订 PDF：16 页，保留文本、表格和页面图像；已有助手对照原文修订的验证方案。`验证样例（虚构数据）` 预期总分 **80.02**，不是用户实际成绩。
- 广东金融学院、湖北理工学院艺术学院、湖南工学院语言与文化学院的官方细则已导入。它们的完整模型方案仍是待核对草稿；独立验收了三种总分结构，不据此宣称全部子项已正确解析。
- 已实际收集教育部中国国际大学生创新大赛 2026 通知及 **10 份官方附件**，并通过官方栏目发现其他近期赛事通知。日期过期会在卡片标明；赛事是否可计入当前学院仍以细则、赛道和认定为准。

详细证据、已知限制与来源见 [验收记录](docs/VALIDATION.md)。

## 计算与证据边界

模型负责读取、解释和生成规则，确定分数由 `app/engine.py` 的受限表达式解释器计算，不执行模型生成的 Python。支持任意数量输入与汇总公式、加权/直接相加/额外加减分、课程学分平均、逐项与分类封顶、条件系数、同项目去重、时间范围和资格提示。

引文匹配与结构校验不能证明模型理解正确。特别是跨页表格、相互冲突的条款、作者贡献、学校认定和年度补充规则，仍需回看原文。无法表达或确定的例外保留在待确认事项中。提分建议以合法参赛、避免漏报和合理投入为目标；计划收益不等于已获得分数。

检索报告展示成功、失败与待处理链接。搜索引擎漏收、访问验证、动态链接、登录后下载和未发布的通知都会限制覆盖，工具不会声称已经找到互联网全部赛事。没有公开附件的公告只保留正文；被验证页拦截时记录失败。

## 开发与复用

```powershell
python -m pytest -q
python -m ruff check app scripts tests
node --check app/static/app.js
node --check app/static/guidance.js
node --check app/static/record-review.js
node --check app/static/score-flow.js
# 首次运行浏览器检查时，如未安装 Chromium：
python -m playwright install chromium
# 基于本机已核对的虚构验收资料，自动建立隔离副本并启动临时服务：
python scripts/check_usability.py
```

不包含本机验收材料的干净副本测试结果为 **28 项通过、16 项跳过**；跳过的是依赖 `artifacts/whu-reviewed-policy.json` 的武大专项验收。完整本机材料下为 **44 项通过**。浏览器验收脚本需要对应的本机验收工作区，不能以缺少这些资料时的跳过结果证明全部学校规则都正确。

`check_usability.py` 在临时 SQLite 库中检查自动保存、自动算分、记录切换、材料核对表单和移动端布局，不修改当前工作区记录，也不调用模型。它需要 `.local/` 中已有已核对方案和虚构验收样例；结果写入 `artifacts/usability-check.json`，以本次运行的实际状态为准。原有完整验收脚本 `scripts/browser_check.py` 仍保留，使用前需按其要求启动服务并载入本机验收资料。

后端 FastAPI + SQLite，前端原生 HTML/CSS/JavaScript，无需 Node 构建。复用了 LearnMargin 的 ZIP/XML 防护代码，保留 [原许可](app/vendor/LEARNMARGIN-LICENSE.txt)；新增分页来源、PDF 表格、视觉校读、文件去重与规则证据链接，没有修改原 LearnMargin 项目。

模型设置流程参考 [DeepTutor](https://github.com/HKUDS/DeepTutor) 和 [OpenMAIC](https://github.com/THU-MAIC/OpenMAIC) 的可配置服务思路；未复制其教学代理实现。当前交付为本地源码应用，未发布线上服务或打包独立 EXE。
